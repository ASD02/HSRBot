# HSRBot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** A Honkai: Star Rail Discord bot covering the 17-feature list, built in four phases that each ship working software.

**Architecture:** discord.py 2.x bot with slash commands, one cog per feature area. Pure logic (gacha math, AV math, schedule math, relic scoring) lives in plain modules with no Discord imports so it is unit-testable. State in SQLite via aiosqlite. Game data is fetched from the community StarRailRes repo into a versioned local cache, never hard-coded.

**Tech Stack:** Python 3.13, discord.py, aiosqlite, aiohttp, cryptography (Fernet), genshin.py (HoYoLAB), pytest.

**Spec:** the user's feature list (17 features) and phase order from the 2026-10-26 conversation; game numbers below are from that list.

## Global Constraints

- Character banner: base 0.6%, soft pity starts pull 74 (+6%/pull), hard pity 90, 50/50 featured.
- Light Cone banner: base 0.8%, soft pity starts pull 64 (+7%/pull), hard pity 80, featured 75%.
- Pity is tracked per banner type.
- AV = 10000 / SPD. Cycle 0 (first) = 150 AV, each later cycle = 100 AV.
- Game data comes from a cached dataset, with a bundled fixture for tests/offline.
- HoYoLAB cookies are encrypted at rest (Fernet), opt-in only, unlink is one command.
- Spoiler content is never posted outside a channel the guild configured for it.
- No network in unit tests.

## Review Focus

- Pity 0 / pity at hard cap / negative or non-integer inputs to calculators: clear error, no crash.
- Autocomplete on empty or very long input: returns <=25 choices, never raises.
- Enka/warp API returns private profile, 4xx, or malformed JSON: friendly message.
- Bot restarted mid-schedule: reminders must not double-fire (persist last-sent).
- Missing env token / missing encryption key: fail at startup with a clear message.
